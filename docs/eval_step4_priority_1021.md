# 4번: 문제점·개선책 우선순위 (2026-10-21)

3번 분석([eval_step3_problems_1021.md](./eval_step3_problems_1021.md))의 문제를 **중요한 순서**로 정리했다. 수정은 사용자가 지시할 때 **한 번에 하나씩**, 같은 270문항(제공 180 + 팀 90)으로 다시 실행해 평가한다.

## 1. 순위를 정한 기준

| 기준 | 설명 |
|---|---|
| 심각도 | 틀렸을 때 사용자에게 주는 피해. 문서에 없는 내용을 확정 답변처럼 내는 것이 가장 크다 |
| 영향 범위 | 영향받는 문항 수 |
| 비용 | 토큰·시간 낭비 |
| 난이도 | 수정할 곳의 수와 위험 |
| 의존성 | 다른 수정 결과를 읽는 데 필요한가 |

## 2. 우선순위 표

| 순위 | 문제 | 영향(Multi-Agent) | 심각도 | 난이도 | 수정 대상 |
|---|---|---|---|---|---|
| 선행 | **측정 보정** (Judge 사람 보정, 팀 negative의 인용 지표 처리) | 모든 비교의 신뢰도 | - | 낮음(사람 작업) | 시스템 변경 없음 |
| 1 | **P2 보류 판단**: 문서에 없는 질문에 `answer` | 8문항(팀 답할 수 없는 질문) | 높음 | 낮음 | 답변 프롬프트 |
| 2 | **P1 답변 완전성**: 조건·예외·단서 누락 | 92문항 (가장 큼) | 중간 | 낮음 | 답변 프롬프트 |
| 3 | **P5 헛된 재검색**: 평균 22,640토큰 | 13문항, 전체 토큰의 약 14% | 중간(비용) | 중간 | 종료 조건(코드) |
| 4 | **P3 되묻기 실패**: 모호한 질문에 답함 | 2문항(기본 RAG 4) | 중간 | 낮음 | 평가 프롬프트 |
| 5 | **P6 검색 양**: 다중 근거 질문의 근거 누락·잘림 | 25 + 4문항 (9문항만 정확성 하락) | 중간 | 낮음(설정값) | `max_parents`, `child_k` |

| 병행 | **P7 추출 오류** | 1문항 (ADD-RP14) | 낮음 | 사람 작업 | 재추출·재적재 |

## 3. 순위의 근거

### 선행. 측정 보정 (시스템 변경 없음, 수정 전에 끝낼 것)
- 이후 모든 개선의 효과를 Judge 점수로 판단하므로, Judge가 사람과 얼마나 일치하는지 먼저 알아야 한다. `06_results/eval/judge_calibration_sample.md` 30문항에 사람 판단을 채운다.
- 기준표를 고치면 **기준선(현재 결과)도 같은 기준표로 다시 채점**한다(Judge 토큰 약 1.8M, 답변 재실행은 필요 없음).
- 팀 골든셋의 답할 수 없는 질문(`expected_behavior`가 abstain 계열)은 인용·문맥 지표에서 빼고 집계한다(코드 집계 규칙 변경, 재실행 불필요).

### 1순위. P2 보류 판단
- **왜 가장 먼저인가**: 문서에 없는 정보에 `answer`로 응답하는 것은 근거 없는 확정 답변으로 이어질 수 있어 심각도가 가장 높다. 수정 위치도 한 곳이다.
- **원인 분해**(Multi-Agent, 답할 수 없는데 `answer`로 답한 8문항): 평가 판정이 `insufficient`인데 재검색 후 `answer`(ADD-HF15, IN15, SE15, POS090) 4, `out_of_scope`인데 답변 단계가 `answer`로 뒤집음(ADD-HP15, POS117) 2, 평가가 `sufficient`로 오판(ADD-PF15, POS120) 2. **6문항은 답변 프롬프트의 "근거 일부만 확인되면 answer" 규칙이 공통 원인**이다.
- **변경 한 가지**: 답변 프롬프트에서 "질문이 묻는 핵심 값(수치·기준일·빈칸·별첨·개인 정보)이 문서에 없으면 관련 내용이 일부 있어도 `abstain`"으로 바꾼다. (평가 프롬프트·종료 조건은 건드리지 않는다.)
- **기대 효과**: 응답 유형 엄격(`behavior_strict`)과 팀 negative 정확도 상승, 해당 8문항 `abstain`.
- **부작용 점검**: 답할 수 있는 문항을 `abstain`하는 과보류(기본 RAG에서 보인 패턴)가 늘지 않는지, 정확성 점수가 내려가지 않는지.

### 2순위. P1 답변 완전성
- **왜 두 번째인가**: 영향 문항이 가장 많고(92) 수정이 쉽다. 다만 P2와 같은 답변 프롬프트를 고치므로 **P2 효과를 읽은 뒤에** 한다(두 변경이 섞이면 원인을 가를 수 없다).
- **변경 한 가지**: 답변 프롬프트에 "질문을 하위 질문으로 나눠 모두 답하고, 문서가 말한 전제·적용 범위·예외·확인 필요 문구를 함께 쓴다(계산은 식과 조건 포함)"를 추가한다.
- **기대 효과**: Judge 정확성 만점 비율(MA 0.589), `must_include` 충족(0.802) 상승.
- **부작용 점검**: 토큰·답변 길이 증가, `must_not` 위반율(현재 0.015)과 충실성(0.998) 하락 여부, P2에서 개선한 abstain 정확도 유지.

### 3순위. P5 헛된 재검색
- **왜 세 번째인가**: 정확도가 아니라 비용 문제다. P2가 적용되면 헛된 재검색 13문항 중 일부(답할 수 없는 문항)는 평가 판정이 달라지지 않는 한 그대로이므로 **P2 이후 재측정해 남는 크기를 보고** 결정한다.
- **변경 한 가지**: 종료 조건에 "직전 라운드와 같은 `missing` 항목이 반복되면 종료"를 추가한다. (재검색 상한 3→2는 다음 비교 후보)
- **기대 효과**: 헛된 재검색 문항의 평균 토큰 감소, 전체 토큰 약 10% 절감 가능, 정확도 동일.
- **부작용 점검**: 재검색으로 회복되던 문항(재검색 문항 22개 중 10개가 통과)의 정확성이 떨어지지 않는지.

### 4순위. P3 되묻기
- **원인**: NEG013·NEG046은 평가가 `sufficient`로 판정했다. 평가 프롬프트의 `ambiguous` 예시("상환일이 언제야?", "이 계좌")가 "상품·약관이 빠진 일반 질문"까지 넓게 잡지 못한다.
- **변경 한 가지**: 평가 프롬프트의 `ambiguous` 기준에 "답이 상품·약관마다 달라지는데 질문에 대상이 없으면"과 예시를 추가한다.
- **부작용 점검**: 답할 수 있는 문항을 `clarify`로 보내는 비율(과도한 되물음).
- 영향이 작아(MA 2문항) 4순위지만, 안전 평가(되묻기) 항목이라 지표로는 의미가 있다.

### 5순위. P6 검색 양
- **왜 뒤인가**: 근거 일부 누락 26문항 중 17문항은 이미 정확성 만점이라 효과가 제한적이고, 문맥이 늘면 입력 토큰이 증가한다.
- **변경 한 가지(순서대로 하나씩)**: ① `max_parents` 5→7 (잘림 4문항에 직접 대응) → ② `child_k` 8→12.
- **부작용 점검**: 입력 토큰 증가, 노이즈로 인한 인용 정확도·충실성 하락.

### 6순위. P4 기본 RAG 과보류
- 기본 RAG를 계속 비교 기준으로만 쓰고 개선 대상으로 삼지 않는다면 보류한다. 삼을 경우 P2와 같은 규칙을 기본 RAG 프롬프트에도 적용해 균형을 맞춘다.

### 병행. P7 추출 오류
- 시스템 변경이 아니라 담당자 작업이다(ADD-RP14, 퇴직연금 17쪽). 해당 문서를 다시 추출·적재하면 청크가 바뀌므로 **다른 개선의 비교 도중에는 하지 말고**, 비교가 끝난 뒤 또는 시작 전에 한 번만 한다.

## 4. 수정·재평가 방식

- 각 수정은 새 커밋으로 남기고, 같은 270문항으로 **기본 RAG와 Multi-Agent를 다시 실행**한 뒤 Judge·경로·실패 분류를 다시 돌려 직전 결과와 비교한다.
- P2·P1·P4(기본 RAG)는 두 파이프라인에 같은 문구로 적용한다. P5·P3·P6은 Multi-Agent에만 해당하므로 기본 RAG 결과는 직전 기준선을 재사용해 비용을 줄인다.
- **재평가 1회의 대략 비용**(현재 실행 기준): Multi-Agent 약 205만 토큰 + 기본 RAG 약 86만 토큰 + Judge 약 180만 토큰 = 약 470만 토큰, 시간은 약 1시간 반. 기본 RAG를 재사용하면 약 295만 토큰이다.
- 비교할 지표: 응답 유형 엄격·완화, Judge 정확성과 만점 비율, `must_include` 충족, `must_not` 위반율, 충실성, 인용 지지, 문맥 Recall, 평균 토큰·시간, 재검색률과 헛된 재검색 수.

## 5. 한 줄 요약

**P2(보류 판단) → P1(답변 완전성) → P5(헛된 재검색) → P3(되묻기) → P6(검색 양)** 순서로 진행하고, 시작 전에 Judge 사람 보정을 먼저 한다.
