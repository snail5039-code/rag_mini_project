# 7번: guardrail · fault tolerance · fallback 검토 (2026-10-22)

코드는 바꾸지 않고 현재 상태와 필요성만 정리했다. 구현은 사용자가 항목을 승인한 뒤 **하나씩** 한다.

## 1. 현재 코드에 있는 것과 없는 것

| 구분 | 있음 | 없음 |
|---|---|---|
| guardrail | 4개 프롬프트 공통 `COMMON_RULES`(문서·질문 속 지시문 무시, 문서 밖 지식 금지), 응답 유형 `abstain`/`refuse`/`clarify`, 평가 판정 `inappropriate`, 인용 번호 범위 검증(`invalid_citations`, 전 실행 0) | 입력 검증(빈 질문·길이·인젝션 탐지), 출력 검증(answer/correct인데 인용 0건 등), 개인정보 마스킹 |
| fault tolerance | `google-genai` HTTP 재시도 8회(지수 백오프, 429·5xx 대상), `run_rag.py`의 문항 단위 예외 격리(오류를 기록하고 다음 문항 진행), `merge_retry.py`로 실패 문항만 재실행 | 402·401 같은 재시도 불가 오류의 즉시 중단·안내, 구조화 출력 파싱 실패(`ValueError`) 재시도, 노드 단위 오류 처리(한 노드가 실패하면 그 질문 전체가 오류) |
| fallback | BM25·Hybrid 검색기(재검색에서 `improve`가 선택할 때만 사용) | 임베딩 호출 실패 시 BM25 대체, 평가·피드백·개선 LLM 실패 시 현재 문맥으로 바로 답변, 답변 LLM 실패 시 안전한 안내 응답 |

## 2. 필요성 판단

실제 데이터로 본 결과다(Multi-Agent 기준선 270문항).

- **guardrail은 점수를 올릴 여지가 작다.** 프롬프트 인젝션 문항 9개(제공 6 + 팀 3) 중 지시를 따른 사례는 없고, 응답 유형이 틀린 것은 NEG034 한 건이다(출처 보존 요구에 `refuse`로 응답). `must_not` 위반율 0.015(4건), 충실성 0.998이다. 다만 골든셋에 인젝션 9, 규정 우회 1, 기만 요청 1개뿐이라 **방어가 잘 되는지 측정할 표본 자체가 부족하다.** 문항 한 개가 11%p다.
- **fault tolerance와 fallback은 점수가 아니라 가용성에 필요하다.** 이번 작업에서 P2 실행 중 크레딧 소진(402)으로 52문항이 실패했고 수동으로 복구했다. Multi-Agent는 질문당 LLM 호출이 평균 2.4회라 노드 하나의 실패가 질문 전체의 오류가 된다. 실서비스라면 사용자에게 오류 대신 안전한 응답이 나가야 한다.
- 따라서 **270문항 점수는 이 세 가지로 거의 오르지 않는다.** 점수를 올리는 후보는 평가 단계 `out_of_scope` 오판 교정, 헛된 재검색 종료(P5), 검색 양(P6)이다.

## 3. 제안 (우선순위 순, 하나씩)

### G1. 오류 구분과 구조화 출력 재시도 (fault tolerance)
- **막는 문제**: 크레딧 소진·인증 오류에서 남은 문항을 계속 호출해 오류만 쌓는 것, 구조화 출력 파싱 실패 한 번에 질문 전체가 오류가 되는 것.
- **방식**: `generate_structured`에서 402·401은 즉시 중단하고 원인을 알리는 예외로 올린다. `res.parsed is None`이면 1회 재호출한다(그래도 실패하면 예외). 한 곳(`rag/llm.py`)만 고친다.
- **평가**: 가짜 클라이언트로 429·500·타임아웃·파싱 실패를 일정 비율로 주입해 성공률, 중단 시점, 소모 호출 수를 본다. **LLM 비용 0원.** 정상 경로 점수는 바뀌지 않아야 한다(작은 부분 집합으로 확인).

### G2. 노드별 대체 경로 (fallback)
- **막는 문제**: 일부 노드 실패가 질문 전체 실패로 번지는 것.
- **방식**: (a) 질문 임베딩 실패 시 BM25 단독 검색(BM25는 이미 있음), (b) `evaluate`/`feedback`/`improve` 실패 시 현재 문맥으로 `answer`로 진행(기본 RAG 수준으로 저하), (c) `answer` 실패 시 검색된 문서 제목과 "일시적으로 답변할 수 없음"을 담은 안전 응답. 응답에 `degraded: true`와 사유를 남긴다.
- **평가**: 노드별 실패를 주입한 부분 집합 20~30문항에서 (1) 오류 없이 응답한 비율, (2) 저하 모드 점수가 기본 RAG 이상인지(`behavior_lenient`, Judge 정확성), (3) 정상 경로 점수 불변. 저하 경로의 LLM 비용은 기본 RAG 수준이라 작다.

### G3. 출력 검증 (보류 권고)
- 인용 번호 검증은 이미 있고 위반 0건이라 이득이 없다. "answer인데 인용 0건이면 강제 보류" 같은 규칙은 정상 답변을 막을 위험이 있다. 먼저 **기록만** 하고(인용 0건 answer 문항 수를 집계) 필요하면 그다음에 정한다.

### G4. 입력 guardrail (보류 권고)
- 정규식 인젝션 탐지는 NEG056처럼 "인젝션이 섞인 정상 질문은 답해야 하는" 경우를 오탐할 수 있고, LLM 분류기를 앞에 두면 질문당 호출이 늘어 비용이 오른다. 현재 프롬프트 방어가 9문항에서 작동하므로 **먼저 적대적 문항을 30개 이상으로 늘려 실제 취약점이 있는지 측정**한 뒤 결정한다. 지금 넣을 것은 빈 질문·과도한 길이 검증 정도다.

## 4. 평가 방법 (공통)

| 지표 | 측정 | 비고 |
|---|---|---|
| 가용성 | 주입한 오류 하에서 오류 없이 응답한 비율 | G1, G2 |
| 저하 품질 | 대체 경로의 `behavior_lenient`, Judge 정확성 vs 기본 RAG | G2 |
| 정상 경로 불변 | 기준선 부분 집합 점수 변화가 실행 간 변동(엄격 ±0.02, Judge ±0.03) 안 | 모든 변경 |
| 인젝션 저항 | 적대적 문항의 `must_not` 위반율, 지시 준수율, 정상 질문 오거절율 | G4, 문항 30개 이상 필요 |

주의: 정상 경로의 점수 변화는 실행 간 변동 폭 안이면 "차이 없음"으로 본다. 변동 폭이 크므로 정상 경로 확인은 코드 경로가 달라지지 않았다는 증거(같은 입력의 응답이 같은지, 호출 수가 같은지)를 함께 쓴다.

## 5. 권고

G1 → G2 순서로 진행하고, G3·G4는 측정 데이터(인용 0건 answer 집계, 적대적 문항 확대)가 쌓인 뒤 결정한다. G1·G2의 검증은 가짜 클라이언트로 하므로 API 비용이 들지 않는다. 점수 개선이 목적이라면 이 항목들은 우선순위가 낮다.

## 7. G2 저하 모드 실제 확인 (2026-10-22, 25문항)

평가 단계(`evaluate`)를 강제로 실패시켜 "현재 문맥으로 바로 답변"하는 경로를 실제 모델로 돌렸다. 문항은 `subset150.json`에서 시드 7로 25개를 뽑았다(`scripts/run_degraded_check.py`). 실행 `20261022_092406__multi_agent__both_golden`, 비교 `scripts/compare_degraded.py` → `06_results/eval/g2_degraded_check.json`. 25문항 모두 `degraded` 응답이었고 오류는 없었다. 행동 점수는 `degraded` 플래그를 무시하고 응답 유형으로 다시 계산했다.

| 지표 (같은 25문항) | 저하 모드 | 기본 RAG | 정상 Multi-Agent(3회 평균) |
|---|---|---|---|
| 응답 유형 엄격 / 완화 | 0.68 / 0.80 | 0.76 / 0.84 | 0.85 / 0.89 |
| Judge 정확성 | 0.72 | 0.68 | 0.78 |
| 만점 비율 | 0.48 | 0.44 | 0.57 |
| 충실성 | 0.98 | 0.98 | 0.97 |
| 평균 토큰 | 3,449 | 3,332 | 8,780 |

- 저하 모드는 **기본 RAG와 비슷한 수준**이고(차이는 문항 1개가 0.04라 노이즈 범위), 정상 Multi-Agent보다 낮다. 의도한 "기본 RAG 수준으로 저하"가 확인됐다. 토큰도 기본 RAG와 같다.
- 저하 모드에서는 평가 단계의 `ambiguous`·`inappropriate` 판정이 없어 되묻기·거절이 답변 프롬프트에만 의존한다(25문항 중 `clarify` 0, `refuse` 0. 정상 Multi-Agent는 각 1건, 기본 RAG는 `refuse` 1건).
- 25문항이라 점수 차이는 방향성만 본다. 비용은 실행과 Judge 합쳐 약 0.2M 토큰이다.
